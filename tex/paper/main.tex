\begin{abstract}
Hierarchical federated learning enables cloud-edge-end collaborative training, but fixed execution and aggregation schemes are insufficient to adapt to heterogeneous and dynamic conditions.
To address this challenge, a dynamic collaboration reconfiguration framework is proposed.
The framework selects collaboration modes according to the current system state and considers execution paths and aggregation strategies.
Moreover, a pre-decision online certificate bound on the joint learning error is composed from client- and mode-specific certificates, accounting for incomplete global fusion and update perturbation.
The certified upper bound and system latency are jointly considered as optimization objectives; if a valid pre-decision certificate is unavailable, the formal decision fails closed.
Feasible collaboration profiles are filtered by Pareto dominance and selected using the Chebyshev ideal point criterion.
An evaluation protocol on CIFAR-10 with ResNet-18 and Fashion-MNIST with LeNet-5 is specified under heterogeneous resource and data conditions; formal runs require valid pre-decision certificates.
\end{abstract}

\section{Introduction}
\label{sec:introduction}
Federated learning (FL) enables multiple end devices to collaboratively train a shared model without transferring raw data to a central server~\cite{fedavg,ZHAO2026108518}. In AIoT systems, however, participating devices differ substantially in computational capability, memory capacity, communication quality, and local data distribution. Cloud-edge-end hierarchical federated learning (HFL) introduces edge servers between end devices and the cloud, providing intermediate aggregation and computation capabilities while reducing direct communication with the cloud~\cite{hfl,FLaTEC2026,yang2026hierarchical}.

Data and system heterogeneity can limit the effectiveness of fixed cloud-edge-end collaboration schemes across clients and training rounds. First, non-IID data can cause
local updates to drift in different directions and can degrade simple weighted
aggregation~\cite{fedavgm,fedprox,scaffold,khan2026accelerating,11214447}.
Second, system capabilities are heterogeneous. A weak end device may be unable
to handle the same workload or meet the same deadline as a stronger device,
whereas an edge or cloud server can undertake more computation~\cite{wang2019adaptivefl,FAN2026108249}.
A mode that suits one client in one round may be inefficient or infeasible
for the same client in another round, or for another client.

Existing work on HFL and cloud-edge-end collaboration has covered personalization,
resource allocation, wireless scheduling, heterogeneous models, and split
training~\cite{Personalizedhfl,JSJX202502007,dinh2021wirelessfl,BSBODP,mazloomi2025multiserver,SFETEC,11185336,YAO2026108495}.
These studies address different aspects of collaborative training. However, dynamically selecting execution and aggregation configurations according to individual client capabilities and changing system conditions remains an important problem.

Different collaboration modes may expose different intermediate information, which affects the choice of protection mechanisms. In this work, differential privacy (DP)~\cite{dwork2006calibrating,mironov2017rdp,11267456} is considered for visible updates, while homomorphic encryption (HE)~\cite{cheon2017ckks,11372457} is considered for encrypted aggregation.

Changing a collaboration mode affects computation placement, communication paths, aggregation, and the resulting global update. These changes influence system latency and learning behavior. To evaluate their effects, system latency and a pre-decision upper bound on the joint learning error are considered. The bound accounts for reference-update deviation, aggregation deviation, and privacy perturbation, and is evaluated from certificates available before training. Resource and protection requirements are treated as feasibility constraints.

This paper studies reconfiguration of cloud-edge-end federated learning at each
selection round under heterogeneous resources and changing system conditions. For
each client, the system evaluates feasible collaboration and protection profiles
under current conditions rather than using one fixed workflow for all clients.
The main contributions are as follows.
\begin{itemize}
    \item A dynamic collaboration configuration space for cloud-edge-end federated learning is formulated, which enables execution and aggregation configurations to be selected according to current system conditions.

    \item A pre-decision online certificate bound on the joint learning error is formulated for each collaboration profile. The bound composes certified ideal-reference and mode radii with aggregate-noise second moments, requires no offline paired clean/private calibration, and is fail-closed when the required evidence is missing. Together with system latency, it forms an optimization problem with two objectives under resource and protection constraints. Feasible configurations are compared using Pareto dominance, and the final configuration is selected using the Chebyshev ideal point criterion.
\end{itemize}

Section~\ref{sec:related_work} reviews related studies

Section~\ref{sec:model} introduces the system model

\section{Related Work}
\label{sec:related_work}
\subsection{HFL Under Heterogeneous Environments}
Existing HFL studies use edge servers for intermediate aggregation between end devices and the cloud~\cite{hfl}. Research on resource management in FL has investigated model pruning under bandwidth and device constraints~\cite{phfl}, adaptive local update frequency and model compression~\cite{xu2022adaptive,wang2019adaptivefl}, and wireless resource allocation~\cite{dinh2021wirelessfl}. Personalized FL and HFL studies have addressed data heterogeneity through client clustering, shared representations, and personalized model components~\cite{sattler2020clustered,collins2021exploiting,Personalizedhfl}. These studies address different aspects of heterogeneous federated training, including resource management, communication efficiency, and model personalization.

Beyond these aspects, heterogeneous device capabilities and changing system conditions can also affect how computation and aggregation are organized across the cloud, edge, and end layers. In this work, a collaboration configuration specifies where model computation is performed, how updates are transmitted, and where aggregation takes place. Different clients may use different configurations, and their configurations may be reconsidered as system conditions change. Since frequent reevaluation incurs computational overhead, we use a configurable selection period to determine when configurations are reevaluated. Related studies have also considered the cost of frequent changes in FL
scheduling decisions and reduced such overhead by maintaining selected client
sets over multiple rounds~\cite{CHEN2026112204,10757319}.

\subsection{Cloud-Edge-End Collaborative Federated Learning}

Cloud-edge-end collaborative FL distributes computation, communication, and aggregation tasks across end devices, edge servers, and the cloud. Different studies have explored how these tasks can be organized. FedAgg~\cite{BSBODP} employs bridge samples and online distillation to support collaboration among models of different sizes across the three layers. SFETEC~\cite{SFETEC} investigates split federated learning in Thing Edge Cloud environments, allowing model computation to be distributed across layers. Related task offloading research has also considered federated learning, privacy protection, and task efficiency in cloud-edge-end systems~\cite{dong2026privacyoffloading}. While these studies investigate different collaborative mechanisms, this work focuses on selecting feasible execution and aggregation configurations for individual clients under changing system conditions.

Task migration in mobile edge computing provides a related perspective on adapting execution placement to changing system conditions. Zhang and Zheng~\cite{ZHANG2019111} investigate task migration decisions under user mobility, while Zhu et al.~\cite{ZHU2024303} study load aware task migration for balancing workloads across edge nodes. Although task migration differs from federated learning collaboration reconfiguration, these studies illustrate the importance of adapting execution placement to system conditions.


\subsection{Privacy Preserving HFL}
Model parameters, gradients, and intermediate representations in federated
training may leak information about private data~\cite{zhu2019dlg}.
Differential privacy (DP) and homomorphic encryption (HE) are widely used
privacy protection techniques in FL~\cite{dwork2006calibrating,cheon2017ckks}.
For HFL, group local DP provides personalized privacy through sampling,
randomized response, and shuffling~\cite{GLDP}.
Adaptive DP FL studies have explored dynamic privacy budget allocation,
adaptive clipping, and client selection for adjusting privacy protection
during training~\cite{xu2025adpfl}.
Other HFL studies combine DP based protection and CKKS based HE for privacy
preserved data sharing scenarios~\cite{PPHFL}.
Related fog FL studies combine hierarchical aggregation, personalization, and DP
for IoT intrusion detection~\cite{islam2025pphffl}.
These studies mainly focus on the security guarantee, budget allocation, or
accuracy degradation of a particular privacy mechanism.
These studies mainly focus on the design, analysis, or adaptation of individual
privacy mechanisms. In this work, privacy requirements are considered jointly
with execution and aggregation configuration selection in cloud-edge-end
federated learning.

This paper jointly considers execution, aggregation, and protection
configuration in federated learning.
Existing categories optimize selected resources, training steps, or privacy
parameters within a prescribed collaboration structure. The proposed collaboration space enables different execution locations,
aggregation paths, transmitted objects, and privacy mechanisms to be compared
within one feasible decision model.
\section{Model Construction}
\label{sec:model}
\subsection{Collaborative Mode and Transmission Modeling}
\label{sec:link_model}

We consider a three-tier federated learning system
consisting of \(N\) clients, a set of edge servers,
and a central cloud server. Each client \(i\) is
associated with an edge server \(e(i)\). At round
\(t\), the system assigns a collaboration mode
\(h_i^t\in\mathcal H\) to each participating client,
allowing training and aggregation to be organized
across different tiers.

intermediate information with the Edge or Cloud tier during training.
Interface II submits a model update to the Edge or Cloud for aggregation
after local training. Interface III submits an aggregated Edge update to
the Cloud after Edge aggregation.

Let L, E and C denote the Local, Edge and Cloud, respectively. Let I, II and III indicate three interfaces. Seven client-level collaboration models are considered in this study and they are collected in the set \(\mathcal H\):
\begin{equation}
\mathcal H=
\{\mathrm{LIE},\mathrm{LIIE},\mathrm{LIC},\mathrm{LIIC},
\mathrm{LIEIIC},\mathrm{LIEIIIC},\mathrm{LIIEIIIC}\}.
\label{eq:seven_modes}
\end{equation}
For instance, LIE (\(L\)-I-\(E\)) enables split
training between the Local and Edge tiers,
whereas LIEIIC (\(L\)-I-\(E\)-II-\(C\)) additionally forwards the resulting
update from the Edge to the Cloud through
Interface II. In LIEIIIC
(\(L\)-I-\(E\)-III-\(C\)), split training and
Edge aggregation are repeated before the
aggregated Edge update is transmitted to the
Cloud through Interface III.


Under split training modes, the model is partitioned
across the participating tiers, with
\(M_L^{h_i^t}\), \(M_E^{h_i^t}\), and
\(M_C^{h_i^t}\) denoting the sets of model
parameters assigned to the Local, Edge, and Cloud
tiers, respectively.
Here, \(|M_k^{h_i^t}|\) represents the number
of model parameters deployed at tier
\(k\in\{L,E,C\}\).
The relative parameter counts characterize the
model placement distribution, whose variation
across consecutive rounds is used to approximate
the redistribution overhead caused by
collaboration mode switching.

In contrast, local training modes
perform model training on the client before
transmitting the resulting update for aggregation.
Split execution is admitted only when
the participating remote training tier
is trusted and satisfies the required
resource constraints. Under this trust
assumption, intermediate activations
and backward gradients exchanged with
that tier do not require additional
DP perturbation.
In all seven modes, raw training data remain
on the client.

\subsubsection{Collaborative Link Blocks and Mode Flows}
We characterize each collaboration mode using
two basic training blocks. Let \(L_B\) be the number of training steps in each block. The split training
block \(S_{Lr}(L_B)\), where \(r\in\{E,C\}\),
represents \(L_B\) training steps performed
jointly by the Local tier and the Edge or
Cloud tier through split learning. The local
training block \(T_L(L_B)\) represents
\(L_B\) training steps performed entirely
at the Local tier, followed by the generation
of a model update for aggregation.

The collaboration flow of each mode specifies
the sequence of training, update transmission,
and aggregation. Let \(A_E\) and \(A_C\)
denote Edge and Cloud aggregation, respectively.
For hierarchical modes, \(E_B\) denotes the
number of Edge-level training and aggregation
stages performed before the aggregated update
is forwarded to the Cloud.

With these definitions, seven mode flows can be represented by the following procedures, where "\(\to\)" is used to denote direction of data transmition, "upd" means the data updating process is involved in data transmition:
\begin{equation}
\begin{aligned}
\mathrm{LIE}:~~&
S_{LE}(L_B) \rightarrow A_E,\\
\mathrm{LIIE}:~~&
T_L(L_B) \xrightarrow{\mathrm{upd}} A_E,\\
\mathrm{LIC}:~~&
S_{LC}(L_B) \rightarrow A_C,\\
\mathrm{LIIC}:~~&
T_L(L_B) \xrightarrow{\mathrm{upd}} A_C,\\
\mathrm{LIEIIC}:~~&
S_{LE}(L_B)
\xrightarrow{\mathrm{upd}} A_C,\\
\mathrm{LIEIIIC}:~~&
\bigl[S_{LE}(L_B)\rightarrow A_E\bigr]^{E_B}
\xrightarrow{\mathrm{upd}} A_C,\\
\mathrm{LIIEIIIC}:~~&
\bigl[
T_L(L_B)
\xrightarrow{\mathrm{upd}} A_E
\bigr]^{E_B}
\xrightarrow{\mathrm{upd}} A_C .
\end{aligned}
\label{eq:mode_flows}
\end{equation}

\subsection{Lifetime Privacy Accounting}
\label{sec:privacy_model}

Sample-level differential privacy~\cite{dwork2014the}
is enforced through Gaussian mechanisms~\cite{abadi2016deep}
during private training and on protected
cross-tier releases, as required by the
selected collaboration mode. For each client,
R\'enyi differential privacy (RDP)~\cite{mironov2017renyi}
is used to accumulate privacy loss across
training rounds. Let \(\mathcal A\) denote
the set of R\'enyi orders~\cite{vanerven2014renyi}. For a Gaussian
mechanism with noise multiplier \(\sigma\),
the RDP cost at order \(\alpha\in\mathcal A\)
is \(\rho(\alpha,\sigma)=\alpha/(2\sigma^2)\).


Let \(m_i^t\) denote the number of Gaussian
mechanisms applied to client \(i\) in round
\(t\), with corresponding noise multipliers
\(\sigma_{i,k}^t\).
The accumulated RDP cost can be calculated as
\begin{equation}
\Phi_i^{t+1}(\alpha)
=
\Phi_i^t(\alpha)
+
\sum_{k=1}^{m_i^t}
\rho(\alpha,\sigma_{i,k}^t).
\label{eq:rdp_update}
\end{equation}
For a given privacy parameter \(\delta\),
the corresponding privacy loss is
\begin{equation}
\epsilon_i^t
=
\min_{\alpha\in\mathcal A}
\left[
\Phi_i^t(\alpha)
+
\frac{\log(1/\delta)}{\alpha-1}
\right].
\label{eq:rdp_to_dp}
\end{equation}
Let \(\bar{\epsilon}\) denote the lifetime
privacy budget of each client. The accumulated
privacy loss must satisfy
\(\epsilon_i^t\leq\bar{\epsilon}\)
throughout training process.

For client \(i\) and candidate mode \(h\),
let \(N_i^t(h)\) denote the approximate
number of Gaussian mechanisms over the
remaining training rounds, based on the selected mode flow and
the planned Gaussian operations in
its minibatch training schedule.
Let \(R\) denote the total number of
training rounds. For example, in LIIEIIIC mode,
with one DP-SGD mechanism per training step.

For \(N_i^t(h)>0\), the noise multiplier
\(\sigma_i^t(h)\) is calibrated to satisfy
\begin{equation}
\min_{\alpha\in\mathcal A}
\left[
\Phi_i^t(\alpha)
+
\frac{N_i^t(h)\alpha}
{2[\sigma_i^t(h)]^2}
+
\frac{\log(1/\delta)}{\alpha-1}
\right]
\leq\bar{\epsilon}.
\label{eq:noise_calibration}
\end{equation}
The smallest feasible multiplier is selected.
If calibration is infeasible, the candidate
mode is excluded. No calibration is required
when \(N_i^t(h)=0\).

For Edge group \(g\), the noise multiplier
is defined as
\begin{equation}
\sigma_g^t=\max_{i\in\mathcal G_g}\sigma_i^t(h_i^t)
\end{equation}

Before execution, the planned privacy cost
is checked against the remaining budget.
The privacy ledger is updated using the
executed Gaussian mechanisms, and the resulting
RDP state is used for mode selection in
the next round.
\subsection{Joint Cost and Utility Modeling}
\label{sec:cost_utility_model}
Each collaboration mode is evaluated in terms
of resource feasibility, round latency, and
learning error, subject to the lifetime
privacy budget in Sec.~\ref{sec:privacy_model}.
\subsubsection{End Side Resource Feasibility}
\label{sec:end_resource}

Let \(W_{i,L}^{\mathrm{comp}}(h_i)\) and
\(M_{i,L}^{\mathrm{mem}}(h_i)\) denote the
computation and memory requirements of
device \(i\) under mode \(h_i\), and let
\(Q_{\mathrm{comp},i}\) and \(Q_{\mathrm{mem},i}\)
denote its available capacities.
The resource feasible mode set is
\begin{equation}
\mathcal H_i^{\mathrm{res}}
=
\left\{
h_i\in\mathcal H
\mid
W_{i,L}^{\mathrm{comp}}(h_i)\le Q_{\mathrm{comp},i},
\;
M_{i,L}^{\mathrm{mem}}(h_i)\le Q_{\mathrm{mem},i}
\right\}.
\label{eq:resource_feasible}
\end{equation}


If any full local update mode is feasible
under the resource constraints, the
candidate set is restricted to such modes.
Otherwise, split modes are considered
only when the participating remote
training tier is trusted and has sufficient
resources. All candidate modes must also
satisfy the lifetime privacy constraint.

\subsubsection{Path and Round Latency on a Common Timeline}

As in Fig \ref{fig:time},
the execution, transmission, and
aggregation events of the selected collaboration
modes on a common timeline are used to determine their
arrival times and the resulting round latency.

\textbf{Transmission latency.}
For a payload \(b\) transmitted from tier \(u\)
to tier \(v\), let \(S_{u,v,b}^t(h_i)\) denote
the original payload size under collaboration
mode \(h_i\). Let \(B_{i,u,v}^t\) denote
the transmission rate of the link between
tiers \(u\) and \(v\) for client \(i\) in
round \(t\), and let \(D_{u,v}^{0}\) denote
the fixed transmission delay of this link.
\begin{equation}
T_{u,v,b}^{\mathrm{link},t}(h_i)
=
\frac{
\kappa\!\left(\pi_i^{t,h_i}(u,v,b)\right)
S_{u,v,b}^t(h_i)}
{B_{i,u,v}^t}
+
D_{u,v}^{0}
+
T_{u,v,b}^{\mathrm{priv},t}
\!\left(\pi_i^{t,h_i}(u,v,b)\right).
\label{eq:comm_latency}
\end{equation}
Here, \(\kappa(\cdot)\) denotes the payload
expansion factor, and
\(T_{u,v,b}^{\mathrm{priv},t}(\cdot)\)
denotes the protection processing time.
For unprotected transmissions,
\(\kappa(\mathrm{none})=1\) and
\(T_{u,v,b}^{\mathrm{priv},t}(\mathrm{none})=0\).

\textbf{Execution latency.}
Let \(\tau_{i,L}^t(h_i)\) and
\(\tau_{i,E}^t(h_i)\) denote the estimated
execution times per training step at the
Local and Edge tiers, respectively.
For Local--Edge split modes, the latency
model assumes pipelined execution across
\(L_B\) training steps, giving
\begin{equation}
T_i^{\mathrm{stage},t}(h_i)
=
L_B\max\!\left\{
\tau_{i,L}^t(h_i),\tau_{i,E}^t(h_i)
\right\}
+
\min\!\left\{
\tau_{i,L}^t(h_i),\tau_{i,E}^t(h_i)
\right\}.
\label{eq:execution_latency}
\end{equation}
For full local training,
\(T_i^{\mathrm{stage},t}(h_i)
=L_B\tau_{i,L}^t(h_i)\).
For modes with repeated training stages,
the corresponding stage duration is
multiplied by \(E_B\).

\textbf{Reconfiguration latency.}
Changing the collaboration mode may require
redistributing model components across the
Local, Edge, and Cloud tiers.
We model the resulting reconfiguration delay as
\begin{equation}
T_i^{\mathrm{sw},t}
=
\eta_h \mathbb{I}(h_i^t\neq h_i^{t-1})
+
\eta_p
\frac{
\|\mathbf{p}(h_i^t)-\mathbf{p}(h_i^{t-1})\|_1
}{2},
\label{eq:switching_cost}
\end{equation}
where $\eta_h$ and $\eta_p$ are the coefficients
for the mode change cost and the placement
change cost, respectively
~\cite{CHEN2026112204,li2026latency},
and $\mathbb{I}(\cdot)$ denotes the indicator function. The normalized model placement is
\begin{equation}
\mathbf{p}(h)
=
\frac{
\left[
\lvert M_L^{h}\rvert,
\lvert M_E^{h}\rvert,
\lvert M_C^{h}\rvert
\right]
}{
\lvert M_L^{h}\rvert+
\lvert M_E^{h}\rvert+
\lvert M_C^{h}\rvert
}.
\label{eq:model_placement_vector}
\end{equation}

\textbf{Path arrival and aggregation.}
For each candidate mode \(h_i\), the mode flow
determines the sequence of execution stages
and payload transmissions leading to the
relevant aggregation point.
We calculate update arrival times by
following this sequence and accounting for
execution, transmission, and reconfiguration
delays in their order of occurrence.
Let \(a_{i,E}^t\) and \(a_{i,C}^t\) denote
the arrival times of client \(i\)'s update
at the Edge and Cloud, respectively,
when the corresponding aggregation point
is involved in the selected mode.

Given a selected mode profile
$\mathbf h^t=(h_1^t,\ldots,h_N^t)$,
for an Edge aggregation group $g$,
let \(\mathcal G_g\) denote its
participating clients.
Edge aggregation begins after all required
client updates have arrived.
Its completion time is
\begin{equation}
f_{g,E}^t
=
\max_{i\in\mathcal G_g} a_{i,E}^t
+
T_{g,E}^{\mathrm{agg},t},
\label{eq:edge_agg_finish}
\end{equation}
where \(T_{g,E}^{\mathrm{agg},t}\) is the Edge aggregation duration. Updates arriving earlier remain buffered until aggregation starts.

For modes that forward an Edge aggregation
result to the Cloud, transmission begins
after the Edge aggregation completes at
time \(f_{g,E}^t\).
Let \(a_{g,C}^t\) denote the arrival time
of this result at the Cloud, including
the Edge to Cloud transmission latency.
Modes that transmit updates directly
to the Cloud instead produce client
arrival times \(a_{i,C}^t\).
Cloud aggregation waits for all required
updates from the applicable paths.
Its completion time is
\begin{equation}
f_C^t
=
\max\left\{
\max_i a_{i,C}^t,\,
\max_g a_{g,C}^t
\right\}
+
T_C^{\mathrm{agg},t},
\label{eq:cloud_agg_finish}
\end{equation}
where the two maxima are taken over the direct Cloud clients and the Edge
groups participating in the current Cloud aggregation, respectively.

As illustrated in Fig.~\ref{fig:time},
the system round latency is measured
with respect to the Cloud aggregation round.
Edge-only paths do not introduce Cloud
synchronization dependencies.
When required, return transmissions begin
after Cloud aggregation completes.
The system round latency is therefore
\begin{equation}
\begin{aligned}
T_{\mathrm{sys}}(\mathbf h^t)
={}&f_C^t+\max\Bigg\{
\max_{i\in\mathcal H^t}
\Big(
T_{C,E,b_i}^{\mathrm{link},t}(h_i^t)
+
T_{E,L,b_i}^{\mathrm{link},t}(h_i^t)
\Big),\\
&\qquad
\max_{i\in\mathcal D^t}
T_{C,L,b_i}^{\mathrm{link},t}(h_i^t)
\Bigg\}.
\end{aligned}
\label{eq:system_round_latency}
\end{equation}
Here, $\mathcal H^t$ and $\mathcal D^t$
denote the hierarchical and direct-cloud
client sets participating in Cloud
aggregation, respectively.
Return delays are evaluated using
(\ref{eq:comm_latency}), with absent
return paths excluded from the maximum.

\subsubsection{Joint Learning Error Modeling}
\label{sec:learning_cost}

The learning objective measures the deviation
of the actual Cloud update from an ideal
gradient step update, accounting for errors arising
from training, aggregation, and privacy
mechanisms.

\textbf{The mean and covariance of training perturbation.}\ 
For client $i$ under mode $h_i^t$,
let $u_{i,0}^t$ and $u_{i,s}^t$
denote the updates obtained without
and with privacy protection, respectively,
under the same training configuration.
The difference between these updates is
\begin{equation}
D_i^t=u_{i,s}^t-u_{i,0}^t.
\end{equation}
By using $D_i$, the perturbation mean and covariance are
calculated by
\begin{equation}
b_i^t=\mathbb E_t[D_i^t]
\end{equation}
and
\begin{equation}
V_{ij}^t=\operatorname{Cov}_t(D_i^t,D_j^t).
\end{equation}

\textbf{The mean and covariance of aggregation perturbation.}\ 
Let $n_i$ denote the number of training
samples at client $i$. The reference
aggregation weight is defined by
\begin{equation}
p_i=\frac{n_i}{\sum_{j=1}^{N}n_j}.
\end{equation}
For a mode profile
\(\mathbf h^t=\left(h_1^t,\ldots,h_N^t\right)\),
let \(\mathcal C^t\)
denote the clients contributing to the
Cloud update.
In case that \(\mathcal C^t\) is nonempty,
their effective aggregation weights can be defined by
\[
a_i^t=
\begin{cases}
\displaystyle
\frac{n_i}{\sum_{j\in\mathcal C^t}n_j},
& i\in\mathcal C^t,\\
0, & \text{otherwise}.
\end{cases}
\]
In case that \(\mathcal C^t\) is empty, \(a_i^t=0\).

Let \(\Delta_{F,0}^t=\sum_i p_i u_{i,0}^t\)
and
\(\Delta_{P,0}^t=\sum_i a_i^t u_{i,0}^t\) respectively be 
full-participation reference and 
profile-specific update
without privacy protection.
The aggregation error can be defined by
\begin{equation}
e_{\mathrm{agg}}^t
=
\sum_i(a_i^t-p_i)u_{i,0}^t.
\label{eq:aggregation_error}
\end{equation}

%The full-participation clean reference
%and the profile-specific clean update are
%\(\Delta_{F,0}^t=\sum_i p_i u_{i,0}^t\)
%and
%\(\Delta_{P,0}^t=\sum_i a_i^t u_{i,0}^t\),
%respectively. Their difference defines
%the aggregation error:
%\begin{equation}
%e_{\mathrm{agg}}^t
%=
%\sum_i(a_i^t-p_i)u_{i,0}^t.
%\label{eq:aggregation_error}
%\end{equation}

Let \(\Delta_*^t=-\eta_t\nabla F(w^t)\)
be the ideal gradient step.
The clean algorithmic error is
\(e_{\mathrm{alg}}^t
=\Delta_{F,0}^t-\Delta_*^t\).
The actual Cloud update satisfies
\begin{equation}
\Delta_s^t
=
\sum_i a_i^t u_{i,s}^t
=
\Delta_*^t
+
e_{\mathrm{alg}}^t
+
e_{\mathrm{agg}}^t
+
\sum_i a_i^tD_i^t.
\label{eq:actual_cloud_update}
\end{equation}
The aggregated perturbation mean and
covariance are
\begin{equation}
    b_s^t=\sum_i a_i^t b_i^t
\end{equation}
and
\begin{equation}
    V_s^t=\sum_{i,j}a_i^ta_j^tV_{ij}^t.
\end{equation}
Therefore,
the total update error as
\(e_{\mathrm{upd}}^t=\Delta_s^t-\Delta_*^t\).

\textbf{The mean and covariance of total update.}\ 

The conditional expected squared error is
\begin{equation}
J_{\mathrm{learn}}^t(\mathbf h^t)
=
\mathbb E_t\|e_{\mathrm{upd}}^t\|_2^2
=
\left\|
e_{\mathrm{alg}}^t+
e_{\mathrm{agg}}^t+b_s^t
\right\|_2^2
+
\operatorname{Tr}(V_s^t).
\label{eq:j_learn_exact}
\end{equation}


For mode selection, the exact quantity
in (\ref{eq:j_learn_exact}) is not estimated
from offline paired clean/private runs.
Instead, a pre-decision conditional upper bound
$\overline J^t(\mathbf h^t)\ge
J_{\mathrm{learn}}^t(\mathbf h^t)$
is evaluated from certificates that are available
before any client trains in round $t$.
Let $\gamma$ be the Cloud step scale and let
$\hat v_i^t$ be a certified pre-decision reference
for the ideal client contribution
$v_i^t=-\eta_*\nabla F_i(w^t)$.
Each certificate supplies a reference radius
$r_i^{\mathrm{ref}}$ with
$\|v_i^t-\hat v_i^t\|_2\le r_i^{\mathrm{ref}}$,
a mode radius $r_i^{\mathrm{mode}}(h_i)$ with
$\|u_{i,0}^t(h_i)-v_i^t\|_2\le r_i^{\mathrm{mode}}(h_i)$,
and an aggregate-share standard deviation
$\sigma_i^t$. Define
\begin{align}
C^t(\mathbf h^t)&=
\left\|\sum_i(\gamma a_i^t-p_i)\hat v_i^t\right\|_2,
\label{eq:online_center}\\
R_{\mathrm{ref}}^t(\mathbf h^t)&=
\sum_i|\gamma a_i^t-p_i|r_i^{\mathrm{ref}},
\label{eq:online_ref_radius}\\
R_{\mathrm{mode}}^t(\mathbf h^t)&=
\gamma\sum_{i\in\mathcal C^t}
a_i^tr_i^{\mathrm{mode}}(h_i),
\label{eq:online_mode_radius}\\
R^t(\mathbf h^t)&=
R_{\mathrm{ref}}^t(\mathbf h^t)
+R_{\mathrm{mode}}^t(\mathbf h^t),
\label{eq:online_radius}\\
Q^t(\mathbf h^t)&=
d\sum_{i\in\mathcal C^t}
\bigl(\gamma a_i^t\sigma_i^t\bigr)^2,
\label{eq:online_q}
\end{align}
where $d$ is the parameter dimension and the
aggregate shares are conditionally zero-mean and
conditionally uncorrelated before secure aggregation.
If a numerical RMS error $r_{\mathrm{num}}$ is
also certified, then
\begin{equation}
\boxed{
J_{\mathrm{learn}}^t(\mathbf h^t)
\le\overline J^t(\mathbf h^t)
:=\left(
\sqrt{\left(C^t+R^t\right)^2+Q^t}
+r_{\mathrm{num}}
\right)^2.
}
\label{eq:online_upper_bound}
\end{equation}

The bound is conditional on the certificates and on
the assumptions declared with them. In particular, the
global objective must be population-sample-weighted,
the per-client linear decomposition of the Cloud
update must match the executed path, the reference and
mode radii must be independently proved, the privacy
shares must be drawn before secure aggregation with
fixed weights, and the aggregate second moment must be
certified. A per-round manifest entry must exist before
the decision round, carry a nonempty evidence record,
and match the exact candidate identity, including its
mode, link mechanisms, and DP execution plan. If any
required entry, assumption, or bound is missing or
inconsistent, the formal path stops before client
training; there is no fallback to offline calibration,
a legacy fusion surrogate, or a central oracle.
A lower bound is reported only when the aggregate noise
variance and its orthogonality to the clean update are
separately proved; otherwise it is set to zero.
Candidate selection uses $\overline J^t$, the certified
upper bound, and not the exact unknown $J_{\mathrm{learn}}^t$.
Therefore, ranking by $\overline J^t$ is a decision rule;
it is not a certificate that the selected profile has
strictly smaller true joint error than every other
profile.

\subsection{Global Multiobjective Collaborative Optimization}
\label{sec:global_optimization}

For each client, the decision variable is
the collaboration mode
\(h_i^t\in\mathcal F_i^t\), where
\(\mathcal F_i^t\subseteq
\mathcal H_i^{\mathrm{res}}\subseteq\mathcal H\)
contains the modes satisfying the resource
constraints in \eqref{eq:resource_feasible},
the activation rule in
Sec.~\ref{sec:end_resource},
the exposure protection requirements,
and the lifetime privacy constraint.
The protection mechanisms and DP noise
multipliers are determined by the candidate
mode and current privacy ledger.

A complete mode profile is
\(\mathbf h^t=(h_1^t,\ldots,h_N^t)\).
The shared Edge and Cloud aggregation and
admission rules define the system feasible
set
\(\mathcal F_{\mathrm{sys}}^t
\subseteq\prod_{i=1}^N\mathcal F_i^t\).
An execution that is not admitted is
reported as \textsc{skip}.

For each feasible profile, the flow model
evaluates the round duration
\(T_{\mathrm{sys}}(\mathbf h^t)\),
while the pre-decision online certificate yields
the upper bound
\(\overline J^t(\mathbf h^t)\).
The multiobjective optimization problem is
\begin{equation}
\underset{\mathbf h^t\in\mathcal F_{\mathrm{sys}}^t}
{\operatorname{minimize}}
\quad
\begin{bmatrix}
T_{\mathrm{sys}}(\mathbf h^t)\\
\overline J^t(\mathbf h^t)
\end{bmatrix}.
\label{eq:global_multiobjective}
\end{equation}

A bounded Pareto search maintains a
nondominated archive
\(\widehat{\mathcal H}_{\mathrm P}^t\).
Let \(T_{\min}^t,T_{\max}^t\) and
\(\overline J_{\min}^t,\overline J_{\max}^t\)
denote the minimum and maximum objective values
within this archive.
The normalized objectives are
\begin{equation}
\bar T(\mathbf h^t)
=
\frac{
T_{\mathrm{sys}}(\mathbf h^t)-T_{\min}^t
}{
T_{\max}^t-T_{\min}^t+\gamma_n
},
\qquad
\bar J(\mathbf h^t)
=
\frac{
\overline J^t(\mathbf h^t)-\overline J_{\min}^t
}{
\overline J_{\max}^t-\overline J_{\min}^t+\gamma_n
},
\label{eq:pareto_normalization}
\end{equation}
where \(\gamma_n>0\) is a small
normalization constant.

The Tchebycheff criterion selects the
profile minimizing the largest normalized
deviation:
\begin{equation}
\begin{aligned}
D_\infty(\mathbf h^t)
&=
\max\{
\bar T(\mathbf h^t),
\bar J(\mathbf h^t)
\},\\
\mathbf h^{t\star}
&\in
\arg\min_{
\mathbf h^t\in\widehat{\mathcal H}_{\mathrm P}^t
}
D_\infty(\mathbf h^t).
\end{aligned}
\label{eq:selection}
\end{equation}

Equal distances are resolved using
system latency, learning error, and
a stable profile identity, in that order.
Real test accuracy is used only for
experimental evaluation.

\begin{breakablealgorithm}
\caption{Dynamic Collaborative Mode Selection}
\label{alg:selection}
\small
\begin{algorithmic}[1]
\REQUIRE
$R,N,S_P$,
$\{Q_{\mathrm{comp},i},Q_{\mathrm{mem},i}\}_{i=1}^{N}$,
$\{\Phi_i^1(\alpha)\}_{i=1}^{N}$,
and a pre-decision online-J certificate manifest
\ENSURE
$\mathbf h^{t,\star}$ and admission decisions for each round

\FOR{$t=1,\ldots,R$}
    
    \STATE \textbf{Feasible Mode Construction}
    \STATE Determine $\mathcal H_i^{\mathrm{res}}$
    using \eqref{eq:resource_feasible}
    \STATE Calibrate $\sigma_i^t(h_i)$
    using \eqref{eq:noise_calibration}
    \STATE Construct $\mathcal F_i^t$
    using the privacy and activation constraints
    \STATE Construct $\mathcal F_{\mathrm{sys}}^t$
    using the system constraints

    \STATE \textbf{Reconfiguration Decision}
    \IF{$\mathcal F_{\mathrm{sys}}^t=\emptyset$}
        \STATE Assign \textsc{skip} to all clients
    \ELSIF{$t>1$, $\operatorname{mod}(t-1,S_P)\neq0$,
    and the previous configuration remains feasible}
        \STATE $\mathbf h^{t,\star}\leftarrow
        \mathbf h^{t-1,\star}$
    \ELSE
        \STATE \textbf{Objective Evaluation}
        \STATE Generate initial profiles from previous choices,
        latency, coverage, and learning cost
        \STATE Apply required coverage repair
        \STATE Evaluate $T_{\mathrm{sys}}(\mathbf h^t)$ using
        \eqref{eq:system_round_latency}
        \STATE Verify the round-$t$ pre-decision
        online-J certificate; fail closed if it is
        missing or inconsistent
        \STATE Evaluate $\overline J^t(\mathbf h^t)$
        using \eqref{eq:online_upper_bound}

        \STATE \textbf{Multiobjective Selection}
        \STATE Initialize $\widehat{\mathcal H}_{\mathrm P}^t$
        from evaluated profiles using \eqref{eq:global_multiobjective}
        \STATE Explore new profiles by changing one client's
        mode and protection settings
        \STATE Evaluate new profiles using
        \eqref{eq:global_multiobjective} and update
        $\widehat{\mathcal H}_{\mathrm P}^t$ by Pareto dominance
        \STATE Select $\mathbf h^{t,\star}$ using
        \eqref{eq:pareto_normalization} and \eqref{eq:selection}
    \ENDIF

    \STATE \textbf{Training Execution}
    \STATE Apply admission adjustments according to tier capacity
    \STATE Reserve authorized Sample DP costs before execution
    \STATE Execute admitted clients and update the global model
    \STATE Update $\{\Phi_i^{t+1}(\alpha)\}_{i=1}^{N}$
    using \eqref{eq:rdp_update}
    \STATE Refresh the system state
\ENDFOR
\end{algorithmic}
\end{breakablealgorithm}

The CIFAR-10 experiments adopt a pretrained ResNet-18 and freeze its
feature-extraction backbone; only the 5,130 parameters in the final
classification head are updated. We select 24,000 training images and
2,000 test images. The edge-label-skew partition creates

100-client, 10-edge topology assigns ten clients to each edge.

\textbf{Heterogeneous resources and links.}
Each client has an individual compute factor and memory-capacity
factor, and each edge server has its own compute factor. The
heterogeneity parameters in Table~\ref{tab:experimental_settings}
control the dispersion of these capacities. S1 increases both client-
and edge-level heterogeneity; S2 introduces more pronounced temporal
variation in network connectivity. Client--edge, client--cloud, and
edge--cloud links have distinct throughput and propagation delays;
network jitter and a periodic variation component change their
communication conditions across training rounds.

\textbf{Evaluation criteria and baselines.}
Our primary measure is \emph{test accuracy as a function of cumulative
logical time}, reflecting the accuracy--time trade-off under resource
and privacy constraints. We additionally report final accuracy,
late-stage mean accuracy, total logical time, participation rate,
and selection cost.

The baselines include Fixed FedAvg, Fixed SplitFed, Fixed HFL,
Random, Individual Optimal, and NSGA-II. Individual Optimal selects
client modes independently, while NSGA-II uses a multiobjective
population search. Within each scenario, all methods use matched
model initialization, data splits, budgets, and system settings.
The mode ablation changes only the reconfiguration policy.

\subsection{Search Space Reduction and Selection Cost}
\label{sec:exp_search_cost}

\textbf{Objective.}
This experiment measures the reduction in candidate collaboration
profiles and the computation required to select one profile under
the coupled client, edge, and cloud constraints.

\textbf{Procedure.}
For a scenario, we compare the combinatorial profile count with the
feasible-mode search space and the number of complete profiles
evaluated by bounded Pareto search. With seven supported collaboration
modes and $N$ clients, the unconstrained mode space contains $7^N$
profiles. Client-level filtering removes modes that violate resource,
memory, activation, or privacy constraints. The Cartesian product of
the remaining per-client modes is further restricted by shared
edge/cloud admission, coverage, and secure-aggregation rules. The
bounded search then evaluates a limited set of complete profiles and
updates a nondominated archive.

\textbf{Results.}
Results are pending valid pre-decision certificates. No profile
evaluation count or selection-time measurement from the removed
objective is reported.

\subsection{Discussion}
\label{sec:reconfiguration_behavior}
\label{sec:experiment_limits}
The constrained baseline comparison and mode-selection ablation are
designed to examine complementary aspects of system efficiency. They
cannot be executed under the formal online-J objective until real
pre-decision certificates are supplied for every round and candidate
identity. This version therefore does not report numerical comparisons.
The evaluation protocol instead fixes the common initialization, data
split, baseline definitions, certificate manifest, and metric set so
that results can be regenerated without mixing the removed legacy
objectives. The certification boundary is also part of the evaluation:
a missing or invalid certificate stops the formal run before training,
and no diagnostic surrogate is relabeled as certified.

\section{Conclusion}
\label{sec:conclusion}
This paper presented a dynamic cloud-edge-end collaboration reconfiguration
framework for federated learning under resource and privacy constraints. The
unified collaboration space represents execution placement, aggregation
topology, transmitted objects, and return paths as the dynamic decision, while a
mode-specific exposure contract determines where DP and HE are required. The
pre-decision certificate model evaluates latency, communication,
candidate-specific DP distortion, encrypted aggregation overhead, and a
certified upper bound on the joint learning error. Missing or invalid
certificates stop the formal decision; there is no fallback to removed legacy
objectives, offline calibration tables, or oracle diagnostics. The constrained
multiobjective formulation is solved by bounded Pareto search and ideal point
Tchebycheff selection.

The current framework uses profiled computation and link rates in its logical
latency model, while the training process and CKKS aggregation are executed on
one host. Future work will combine online profiling with physical
cloud-edge-end deployment and will further reduce reconfiguration overhead
through parallel profile evaluation, distributed search, and warm starts.

\section{Analysis of Joint Learning Error}
\label{app:convergence_proof}

This appendix establishes the relationship
between the joint learning error in
Sec.~\ref{sec:learning_cost} and the
convergence of the global model.

\subsection{Aggregation Error Bound}

For a fixed mode profile, the aggregation
error is given by
\eqref{eq:aggregation_error}.
The clean updates and aggregation weights
are treated as fixed when evaluating the
conditional privacy perturbation moments.

\begin{lemma}
\label{lem:aggregation_error}
Suppose that
\(\|u_{i,0}^t\|_2\le U_i^t\)
for every client \(i\). Then
\begin{equation}
\|e_{\mathrm{agg}}^t\|_2
\le
\sum_{i=1}^{N}
|a_i^t-p_i|U_i^t.
\label{eq:app_aggregation_bound}
\end{equation}
If \(U_i^t\le U^t\) for all clients, then
\(
\|e_{\mathrm{agg}}^t\|_2
\le U^t\|\mathbf a^t-\mathbf p\|_1
\).
\end{lemma}

\begin{proof}
From \eqref{eq:aggregation_error}
and the triangle inequality,
\begin{equation}
\begin{aligned}
\|e_{\mathrm{agg}}^t\|_2
&=
\left\|
\sum_i(a_i^t-p_i)u_{i,0}^t
\right\|_2\\
&\le
\sum_i |a_i^t-p_i|
\|u_{i,0}^t\|_2\\
&\le
\sum_i |a_i^t-p_i|U_i^t.
\end{aligned}
\end{equation}
Applying the common bound \(U^t\)
gives the second result.
\end{proof}

\subsection{Joint Update Error}

Let \(\mathbb E_t\) denote conditional
expectation given the round information,
selected mode profile, and common
training schedule. Under this conditioning,
the clean reference updates and aggregation
weights are fixed.

Define the aggregated trajectory difference
as \(D_s^t=\sum_i a_i^tD_i^t\).
Using \eqref{eq:actual_cloud_update},
the total update error satisfies
\begin{equation}
e_{\mathrm{upd}}^t
=
e_{\mathrm{alg}}^t
+
e_{\mathrm{agg}}^t
+
D_s^t.
\label{eq:app_update_error}
\end{equation}

\begin{proposition}
\label{prop:joint_error}
Let
\(b_s^t=\mathbb E_t[D_s^t]\)
and \(V_s^t=\operatorname{Cov}_t(D_s^t)\).
Then
\begin{equation}
\mathbb E_t
\|e_{\mathrm{upd}}^t\|_2^2
=
\left\|
e_{\mathrm{alg}}^t+
e_{\mathrm{agg}}^t+b_s^t
\right\|_2^2
+
\operatorname{Tr}(V_s^t).
\label{eq:app_joint_error}
\end{equation}
\end{proposition}

\begin{proof}
Write
\(D_s^t=b_s^t+\zeta_s^t\),
where \(\mathbb E_t[\zeta_s^t]=0\)
and
\(\operatorname{Cov}_t(\zeta_s^t)=V_s^t\).
From \eqref{eq:app_update_error},
\begin{equation}
e_{\mathrm{upd}}^t
=
e_{\mathrm{alg}}^t+
e_{\mathrm{agg}}^t+
b_s^t+\zeta_s^t.
\end{equation}
Expanding its squared norm and taking
conditional expectation eliminates the
cross term involving \(\zeta_s^t\).
Furthermore,
\(\mathbb E_t\|\zeta_s^t\|_2^2
=\operatorname{Tr}(V_s^t)\).
The stated identity follows.
\end{proof}

The covariance satisfies
\(
V_s^t=\sum_{i,j}a_i^ta_j^tV_{ij}^t
\).
When the client perturbations are
conditionally independent,
\(
V_s^t=\sum_i(a_i^t)^2V_{ii}^t
\).
This exact identity is retained as the definition of
the learning error. The formal selection objective does
not estimate the covariance from offline data; it uses
the certified upper bound derived below.

\subsection{Expected Loss and Convergence}

Assume that the global objective
\(F\) is \(\beta\)-smooth, so that
\begin{equation}
F(y)
\le
F(x)+
\langle\nabla F(x),y-x\rangle
+
\frac{\beta}{2}\|y-x\|_2^2.
\label{eq:app_smoothness}
\end{equation}

\begin{proposition}
\label{prop:learning_bound}
Suppose that \(F\) is
\(\beta\)-smooth and
\(0<\eta_t\le 1/\beta\).
For the model update
\(w^{t+1}=w^t+\Delta_s^t\),
the conditional expected loss satisfies
\begin{equation}
\mathbb E_t[F(w^{t+1})]
\le
F(w^t)
-
\frac{\eta_t}{2}
\|\nabla F(w^t)\|_2^2
+
\frac{
J_{\mathrm{learn}}^t(\mathbf h^t)
}{2\eta_t}.
\label{eq:app_expected_descent}
\end{equation}
\end{proposition}

\begin{proof}
By the definition of the total update
error,
\begin{equation}
w^{t+1}
=
w^t-\eta_t\nabla F(w^t)
+e_{\mathrm{upd}}^t.
\end{equation}
Let \(g^t=\nabla F(w^t)\).
Applying \eqref{eq:app_smoothness}
gives
\begin{equation}
\begin{aligned}
F(w^{t+1})
\le {}&
F(w^t)
+
\langle g^t,
-\eta_tg^t+e_{\mathrm{upd}}^t
\rangle\\
&+
\frac{\beta}{2}
\|-\eta_tg^t+e_{\mathrm{upd}}^t\|_2^2.
\end{aligned}
\end{equation}
Since \(\beta\le 1/\eta_t\),
the quadratic term is bounded by
\begin{equation}
\begin{aligned}
\frac{\beta}{2}
\|-\eta_tg^t+e_{\mathrm{upd}}^t\|_2^2
\le {}&
\frac{\eta_t}{2}\|g^t\|_2^2\\
&-
\langle g^t,e_{\mathrm{upd}}^t\rangle\\
&+
\frac{1}{2\eta_t}
\|e_{\mathrm{upd}}^t\|_2^2.
\end{aligned}
\end{equation}
Substitution cancels the inner
products involving
\(e_{\mathrm{upd}}^t\), yielding
\begin{equation}
F(w^{t+1})
\le
F(w^t)
-
\frac{\eta_t}{2}\|g^t\|_2^2
+
\frac{1}{2\eta_t}
\|e_{\mathrm{upd}}^t\|_2^2.
\end{equation}
Taking conditional expectation
and applying
\eqref{eq:j_learn_exact}
completes the proof.
\end{proof}

The bound holds for a biased update
error and does not require
\(\mathbb E_t[e_{\mathrm{upd}}^t]=0\).

For the convergence result, assume
that \(F\) satisfies the
Polyak--Lojasiewicz (PL) condition
with parameter \(\mu>0\):
\begin{equation}
\|\nabla F(w)\|_2^2
\ge
2\mu\bigl(F(w)-F^*\bigr),
\label{eq:app_pl_condition}
\end{equation}
where \(F^*=\inf_w F(w)\).

\begin{corollary}
\label{cor:joint_pl_convergence}
Under the assumptions of
Proposition~\ref{prop:learning_bound}
and the PL condition,
\begin{equation}
\begin{aligned}
\mathbb E_t
[F(w^{t+1})-F^*]
\le {}&
(1-\mu\eta_t)
(F(w^t)-F^*)\\
&+
\frac{
J_{\mathrm{learn}}^t(\mathbf h^t)
}{2\eta_t}.
\end{aligned}
\label{eq:app_pl_recursion}
\end{equation}
\end{corollary}

\begin{proof}
Applying \eqref{eq:app_pl_condition}
to the gradient term in
\eqref{eq:app_expected_descent}
gives the stated recursion.
\end{proof}

For a constant step size
\(\eta_t=\eta\) satisfying
\(0<\mu\eta\le 1\), suppose that
\(J_{\mathrm{learn}}^t(\mathbf h^t)
\le\overline J\)
for all rounds. Setting
\(q=1-\mu\eta\) and taking
successive expectations yields
\begin{equation}
\begin{aligned}
\mathbb E[F(w^T)-F^*]
\le {}&
q^T\bigl(F(w^0)-F^*\bigr)\\
&+
\frac{\overline J}{2\eta}
\sum_{t=0}^{T-1}q^{T-1-t}.
\end{aligned}
\label{eq:app_pl_multiround}
\end{equation}
Consequently,
\begin{equation}
\limsup_{T\to\infty}
\mathbb E[F(w^T)-F^*]
\le
\frac{\overline J}{2\mu\eta^2}.
\label{eq:app_pl_error_floor}
\end{equation}

Thus, the joint learning error
controls the residual term in the
expected convergence bound.
The formal selection objective is the certified
pre-decision upper bound
\(\overline J^t(\mathbf h^t)\ge
J_{\mathrm{learn}}^t(\mathbf h^t)\).
Substituting \(\overline J^t\) for
\(J_{\mathrm{learn}}^t\) in
\eqref{eq:app_expected_descent} preserves the descent
bound, conditional on the certificate assumptions.

\paragraph{Pre-decision online learning-error bound.}
For a candidate profile $\mathbf h^t$, let
$a_i^t(\mathbf h^t)$ be the effective Cloud weight determined by
admission and aggregation topology, and let
$p_i=n_i/\sum_jn_j$ be the population sample weight.
Define the ideal full-gradient step and the ideal client
contribution
\begin{equation}
\Delta_*^t=-\eta_*\nabla F(w^t),
\qquad
v_i^t=-\eta_*\nabla F_i(w^t),
\label{eq:app_ideal_steps}
\end{equation}
so that $\Delta_*^t=\sum_i p_iv_i^t$ when the global objective is
population-sample-weighted, $F=\sum_i p_iF_i$.
The clean Cloud update of the profile is
\begin{equation}
\Delta_{\mathrm{clean}}^t(\mathbf h^t)
=\gamma\sum_{i\in\mathcal C^t}a_i^tu_i^t(h_i),
\label{eq:app_clean_update}
\end{equation}
where $u_i^t(h_i)$ is the noise-free mode update and $\gamma$ is the
Cloud step scale. The privacy-protected Cloud update is
$\Delta_s^t=\Delta_{\mathrm{clean}}^t+\xi^t$, with
$\xi^t=\gamma\sum_{i\in\mathcal C^t}a_i^tz_i^t$ and
$\mathbb E_t[z_i^t]=0$ for every aggregate share.

\textbf{Exact decomposition.}
Let $\hat v_i^t$ be a pre-decision reference for $v_i^t$. Adding and
subtracting $\sum_i(\gamma a_i^t-p_i)\hat v_i^t$ gives, before any norm
inequality,
\begin{equation}
\begin{aligned}
\Delta_{\mathrm{clean}}^t-\Delta_*^t
={}&
\sum_i(\gamma a_i^t-p_i)\hat v_i^t\\
&+\sum_i(\gamma a_i^t-p_i)(v_i^t-\hat v_i^t)\\
&+\gamma\sum_{i\in\mathcal C^t}a_i^t
\bigl(u_i^t(h_i)-v_i^t\bigr).
\end{aligned}
\label{eq:app_online_identity}
\end{equation}
The first term is the certifiable center; the last two terms are the
reference and mode radii. The reference may be stored per client, or as
a shared direction $\hat v_i^t=s_i^td^t$; in the shared form,
$s_i^td^t$ is a deterministic center and $r_i^{\mathrm{ref}}$ must
cover both the client heterogeneity and the reference uncertainty.

\textbf{Certified radii and noise.}
The certificate supplies
\begin{equation}
\|v_i^t-\hat v_i^t\|_2\le r_i^{\mathrm{ref}},
\qquad
\|u_i^t(h_i)-v_i^t\|_2\le r_i^{\mathrm{mode}}(h_i)
\label{eq:app_online_radii}
\end{equation}
for every participating client, and an aggregate-share standard
deviation $\sigma_i^t$ with
$\mathbb E_t\|z_i^t\|_2^2\le d(\sigma_i^t)^2$.
If the shares are conditionally zero-mean and conditionally
uncorrelated,
\begin{equation}
\mathbb E_t\|\xi^t\|_2^2
\le Q^t(\mathbf h^t)
=d\sum_{i\in\mathcal C^t}
\bigl(\gamma a_i^t\sigma_i^t\bigr)^2.
\label{eq:app_online_q}
\end{equation}
Local DP-SGD noise is already included in
$r_i^{\mathrm{mode}}(h_i)$; it must not be counted again in $Q^t$.
Define
\begin{align}
C^t&=\left\|\sum_i(\gamma a_i^t-p_i)\hat v_i^t\right\|_2,\\
R_{\mathrm{ref}}^t&=\sum_i
|\gamma a_i^t-p_i|r_i^{\mathrm{ref}},\\
R_{\mathrm{mode}}^t&=\gamma\sum_{i\in\mathcal C^t}
a_i^tr_i^{\mathrm{mode}}(h_i),\\
R^t&=R_{\mathrm{ref}}^t+R_{\mathrm{mode}}^t.
\end{align}
Then
\begin{equation}
\left\|\Delta_{\mathrm{clean}}^t-\Delta_*^t\right\|_2
\le C^t+R^t.
\label{eq:app_online_clean_bound}
\end{equation}

\begin{proposition}[Pre-decision online joint-error upper bound]
\label{prop:predecision_online_upper}
Condition on the round state, candidate profile, certificates, and
common training schedule. Under
\eqref{eq:app_online_radii} and \eqref{eq:app_online_q}, with the
declared conditional assumptions and a certified numerical RMS error
$r_{\mathrm{num}}$,
\begin{equation}
J_{\mathrm{learn}}^t(\mathbf h^t)
\le\left(
\sqrt{\left(C^t+R^t\right)^2+Q^t}
+r_{\mathrm{num}}
\right)^2
=\overline J^t(\mathbf h^t).
\label{eq:app_online_upper}
\end{equation}
\end{proposition}

\begin{proof}
Let $b^t=\Delta_{\mathrm{clean}}^t-\Delta_*^t$, which is fixed
conditional on the pre-decision information. Since
$\mathbb E_t[\xi^t]=0$, the cross term in
\begin{equation}
J_{\mathrm{learn}}^t
=\mathbb E_t\|b^t+\xi^t\|_2^2
=\|b^t\|_2^2+\mathbb E_t\|\xi^t\|_2^2
\end{equation}
vanishes. By \eqref{eq:app_online_clean_bound},
$\|b^t\|_2\le C^t+R^t$, and by \eqref{eq:app_online_q},
$\mathbb E_t\|\xi^t\|_2^2\le Q^t$. Hence
\begin{equation}
\sqrt{J_{\mathrm{learn}}^t}
\le\sqrt{\left(C^t+R^t\right)^2+Q^t}.
\end{equation}
Adding the certified numerical RMS error in the RMS metric and
squaring yields \eqref{eq:app_online_upper}.
\end{proof}

\paragraph{Bias--variance variant.}
If each mode certificate separately proves conditional centering
$\mathbb E_t[u_i^t-v_i^t\mid\mathcal G^t]=b_i^t$ with
$\|b_i^t\|_2\le\beta_i^t$, conditional second moment
$\mathbb E_t\|u_i^t-v_i^t-b_i^t\|_2^2\le\nu_i^t$, and cross-client
orthogonality of the centered fluctuations given all ideal gradients,
then replace $R_{\mathrm{mode}}^t$ by
$R_{\mathrm{bias}}^t=\gamma\sum_{i\in\mathcal C^t}a_i^t\beta_i^t$ and
add $V^t=\gamma^2\sum_{i\in\mathcal C^t}(a_i^t)^2\nu_i^t$ inside the
square:
\begin{equation}
\overline J_{\mathrm{BV}}^t
=\left(
\sqrt{\left(C^t+R_{\mathrm{ref}}^t+R_{\mathrm{bias}}^t\right)^2
+V^t+Q^t}
+r_{\mathrm{num}}
\right)^2.
\label{eq:app_online_bv}
\end{equation}
Conditional independence of training processes does not imply centered
mode fluctuations or their cross-client orthogonality. The evaluator
requires both assumptions explicitly; otherwise it uses the RMS form.

\paragraph{Parameter-block variant.}
When certificates partition the parameter coordinates into disjoint
contiguous blocks, the evaluator computes per-block centers $C_j$ and
radii $R_j$ and uses
\begin{equation}
\overline J_{\mathrm{block}}^t
=\left(
\sqrt{\sum_j\left(C_j+R_j\right)^2+Q^t}
+r_{\mathrm{num}}
\right)^2.
\label{eq:app_online_block}
\end{equation}
Distinct coordinate blocks are orthogonal as vectors; independence of
the random training errors across blocks is not assumed. The evaluator
uses the smaller of the scalar and block bounds. Blocks are supported
only with the RMS uncertainty model.

\paragraph{Lower bound and certified interval order.}
Because $Q^t$ is an upper bound on noise energy by default, it cannot be
used to lower-bound $J$. If the aggregate noise variance is separately
proved exact and orthogonal to the clean update, set
$Q_{\mathrm{floor}}^t=Q^t$; otherwise set
$Q_{\mathrm{floor}}^t=0$. Then
\begin{equation}
L^t=
\left(
\max\left\{0,\sqrt{\left(s^t\right)^2+Q_{\mathrm{floor}}^t}
-r_{\mathrm{num}}\right\}
\right)^2,
\qquad
s^t=\max\left\{0,C^t-R^t\right\}.
\label{eq:app_online_lower}
\end{equation}
is a lower bound under the corresponding assumptions.
The selection objective remains $\overline J^t$. Given two profiles'
intervals, a strict order is certified only when
$\overline J_{\mathrm{left}}<L_{\mathrm{right}}$ or
$\overline J_{\mathrm{right}}<L_{\mathrm{left}}$; otherwise the order
is undetermined. The implementation exposes this comparison as a
diagnostic and does not use it to rank candidate profiles.

\paragraph{Manifest and fail-closed requirements.}
The evaluator accepts manifests declaring schema
\texttt{dynfl.online\_j.v1} or \texttt{dynfl.online\_j.v2}, with target
\texttt{ideal\_full\_gradient\_one\_step}. Round $t$ is read from the
entry \texttt{round:$t$}; its \texttt{round\_index} and
\texttt{available\_before\_round} must both equal $t$, and the evidence
string must be nonempty. The v2 evaluator requires explicit true
assumptions for population-sample weighting, runtime-matching linear
client contributions, ideal-reference RMS bounds, mode-relative ideal
bounds, pre-secure-aggregation noise timing with fixed weights,
conditional zero-mean and uncorrelated shares, aggregate-share second
moments, and the numerical RMS bound. Each client-mode certificate must
match the exact candidate identity, including mode, link mechanisms, DP
execution plan, and noise multipliers and events. Missing, mismatched,
or unproved entries raise an error before client training. The
evaluator composes supplied certificates; it does not prove that a
runtime, privacy accountant, or noise generator satisfies them.

\paragraph{Additive v1 specialization.}
The v1 schema supplies a reference gradient $g_{\mathrm{ref}}$, an
ideal step $\eta_*$, a Cloud step $\gamma$, a gradient RMS error $r_g$,
and per-client values $s_i$, $r_i$, and $\sigma_i$. With
$a_i=n_i/\sum_{j\in\mathcal C^t}n_j$, the evaluator computes
\begin{equation}
\begin{aligned}
C&=\left|\eta_*-\gamma\sum_{i\in\mathcal C^t}a_i^ts_i\right|
\|g_{\mathrm{ref}}\|_2,\\
R_{\mathrm{ref}}&=\eta_*r_g,\qquad
R_{\mathrm{mode}}=\gamma\sum_{i\in\mathcal C^t}a_i^tr_i,\\
Q&=\gamma^2d\sum_{i\in\mathcal C^t}(a_i^t)^2(\sigma_i^t)^2,
\end{aligned}
\end{equation}
and applies \eqref{eq:app_online_upper}. Its lower bound uses no noise
floor and is
$\bigl(\max\{0,C-R_{\mathrm{ref}}-R_{\mathrm{mode}}-r_{\mathrm{num}}\}\bigr)^2$.
The coupled v2 form is preferred because it centers each client's own
ideal contribution instead of relying on a single global reference
direction.

\paragraph{Optional LIIC optimizer-derived radius.}
For LIIC with LeNet-5, a mode radius can be derived from the actual
clipped-gradient optimizer instead of being supplied directly. The
proof must declare schema \texttt{dynfl.liic.sgd.v1}, LeNet-5, a fresh
zero-momentum \texttt{torch.optim.SGD}, either sample-DP SGD or clipped
SGD, the planned batch sizes and optimizer step count, a certified
ideal reference radius, a matching Gaussian mechanism, and the absence
or explicit modeling of further update transformations. With $K$ steps,
learning rate $\eta$, weight decay $\lambda$,
$\alpha=1-\eta\lambda$, $b_k=\eta\alpha^{K-1-k}$, $S=\sum_kb_k$,
per-step pathwise residual caps $E_k$, and clipping threshold $C$,
\begin{equation}
\begin{aligned}
r_i^{\mathrm{mode}}
\le{}&
\left|\frac{S}{\eta_*}-1\right|\|\hat v_i^t\|_2
+\lambda S\|\theta_0\|_2+\sum_kb_kE_k\\
&+\sqrt{d\sum_kb_k^2
\left(\frac{2C\sigma_i}{B_k}\right)^2}
+r_i^{\mathrm{ref}}+r_{\mathrm{proj}},
\end{aligned}
\label{eq:app_liic_radius}
\end{equation}
where the Gaussian term applies to sample-DP SGD, $B_k$ is the actual
batch denominator, and $r_{\mathrm{proj}}$ is added only when a release
update is clipped. This specialization cannot be applied to ResNet-18
with momentum or weight decay, or to any path whose optimizer, batch
schedule, noise, or transformations differ from the proof.

\paragraph{Connection with the descent guarantee.}
Because \eqref{eq:app_online_upper} bounds
$J_{\mathrm{learn}}^t$ from above, substituting it into
\eqref{eq:app_expected_descent} gives
\begin{equation}
\mathbb E_t[F(w^{t+1})]
\le F(w^t)-\frac{\eta_t}{2}\|\nabla F(w^t)\|_2^2
+\frac{\overline J^t(\mathbf h^t)}{2\eta_t},
\end{equation}
and the PL recursion of Corollary~\ref{cor:joint_pl_convergence} holds
with $\overline J^t$ in place of $J_{\mathrm{learn}}^t$. This does not
turn the certificate into a convergence proof: the radii, noise
moments, and assumptions remain conditional inputs, and the selected
profile minimizes the certified upper bound rather than the unknown
exact joint error.
